# BATCH_004 — ฉากสุสานยานและคีย์เฟรมเอฟเฟกต์

ชุดนี้ส่งตามทางเลือกคีย์เฟรมที่ระบุในBATCH_004.md: ฉาก3ชั้นและเอฟเฟกต์5ชนิด ชนิดละ3คีย์เฟรม รวม18PNG ไม่ใช่47PNGของชุดflipbookเต็ม

## ไฟล์ที่ส่งและเฟรมที่ยังขาด

- ฉาก far/mid/foreground อย่างละ1ภาพ
- explosion_small:000,006,011 จากทั้งหมด12เฟรม
- impact_spark/joint_break/detach_burst/shield_hit:000,004,007 จากชนิดละ8เฟรม

เอฟเฟกต์ส่ง15คีย์เฟรมจาก44เฟรมเต็ม ยังมี29เฟรมกลางที่ไม่ได้สร้าง ไม่มีการคัดลอกภาพเดิมหรือแปะเฟรมว่างเพื่ออ้างว่าครบ ชื่อไฟล์เลขข้ามเฟรมตั้งใจตามคำขอ ห้ามตัวimporterถือว่าไฟล์หายโดยไม่ดูframe_plan.json

## นำเข้าเกม

เก็บต้นฉบับไว้และย่อสำเนาimportตามขนาดเป้าหมาย ดูrequested_canvas/actual_canvasในdelivery_manifest.json ฉากใช้สัดส่วน3:4 เอฟเฟกต์เป็นsquare เป้าหมาย1536×2048/512×512อาจต่างจากผลจริง เครื่องมือไม่ได้รับรองขนาดตรงทุกครั้ง

farเป็นopaque; mid/foregroundและเอฟเฟกต์ใช้alphaจริง เอฟเฟกต์additiveยังมีalphaและไม่ควรลบglowด้วยcolor-key ร่างท้ายเป็นเศษแสง/ควันจาง ไม่จำเป็นต้องว่างสนิท; ให้runtimefadeเป็น0เมื่อจบclip

คีย์เฟรมเริ่ม/กลาง/ท้ายยังไม่ใช่flipbookที่เล่นลื่นพร้อมใช้ Claudeอาจทำcrossfadeและscaleระหว่างคีย์เฟรมร่วมparticles หรือส่งขอเฟรมกลางเพิ่ม ห้ามอ้างว่าการinterpolateภาพทำให้ทุกเปลวไฟ/เศษโลหะต่อเนื่องสมบูรณ์แล้ว การยืนยันpivotและtemporal coherenceต้องดูตอนเล่นจริง

## ฉากเลื่อนและการต่อขอบ

ตรวจตัวเลขขอบบน/ล่างในbackground_QA.json: ความต่างRGBของfarเป็นเพียงการตรวจseamตรงขอบ ไม่รับรองความต่อเนื่องของลวดลายด้านใน หากไม่เท่ากันทุกพิกเซล ให้Claudeใช้การblendขอบในruntimeหรือเตรียมสำเนาtextureแบบtileableก่อนrelease อย่าตั้งrepeatแล้วอ้างว่าไร้รอยต่อโดยไม่ได้ทดสอบ

mid/foregroundควรไม่มีพิกเซลทึบตรงขอบบน/ล่าง ส่วนขอบซ้าย/ขวาของเศษซากอาจถูกออกแบบให้พ้นviewportขณะparallax ตรวจรายงานและภาพจริง ไม่เอาวัตถุbackgroundเป็นcolliderอัตโนมัติ ชั้นกลาง/หน้าต้องไม่บดบังกระสุนหรือแสงเตือน Renderกระสุนศัตรูเหนือชั้นvisualที่จำเป็น
