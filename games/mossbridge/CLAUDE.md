## 1. เป้าหมาย

เกม MMORPG 2D บนเบราว์เซอร์ สไตล์ chibi hand-painted โลก cozy fantasy (เมือง Mossbridge)
ระบบเด่นคือใส่หมวก/ของสวมหัวแล้วเห็นบนตัวละคร (กลไก paper-doll แบบ Ragnarok Online แต่ภาพ ชื่อ และโลกเป็นของเราเองทั้งหมด ห้ามลอกเกมใด)

**เจ้าของโปรเจ็คบอกไว้ชัดเจน:**
- สไตล์ภาพตอนนี้ "ใช่เลย ชอบมาก" ห้ามเปลี่ยนแนวภาพ (ดู `refs/` ใน `chatgpt-pack/` และ `art/reference/`)
- **งานหลักตอนนี้คือทำให้การเดินและการโจมตีของทั้งตัวละครและมอนสเตอร์เนียนกว่าเดิม** (ดู §5)
- ไม่รีบ เน้นคุณภาพ ทำทีละขั้น ตรวจด้วยตาทุกครั้ง
- ภาพทั้งหมดสร้างด้วย **ChatGPT** (บนแอปเดสก์ท็อปให้ Claude เปิด chatgpt.com ผ่านเบราว์เซอร์แล้วสั่งเอง ดู §4)
- สื่อสารกับเจ้าของเป็นภาษาไทย ส่วนโค้ด ชื่อไฟล์ และ commit message เป็นภาษาอังกฤษ

## 3. วิธีรันและทดสอบ

```bash
cd games/mossbridge
npm install                 # ติดตั้ง playwright สำหรับ QA
npx playwright install chromium
npm run serve               # เปิด http://localhost:8000  (file:// ใช้ไม่ได้ เพราะ WebGL โหลดรูปจาก file ไม่ได้)
# อีกหน้าต่าง:
npm run qa:frames -- '[{"view":"se","walk":1,"n":8,"dt":0.05},{"view":"sw","clip":"slash3","ts":[0.1,0.2,0.3,0.38,0.5]}]'
npm run qa:sheet            # รวมเฟรมเป็น qa-out/sheet.png แล้วเปิดดูด้วยตา
npm run qa:sim              # จำลองการสู้ 90 วินาที ต้องจบแบบ "no errors"
npm run qa:video            # อัดวิดีโอเล่นจริง 12 วินาที -> qa-out/video/ (ใช้ GPU จริงจะลื่น)
npm run qa:rig              # ตรวจ rig แบบไม่ใช้เบราว์เซอร์: ท่าพักตรงภาพวาด, เท้าไม่ลื่น 12 ทิศ x เดิน/วิ่ง, เท้ากลับที่หลังหยุด
npm run rig                 # ตัดชิ้นส่วนใหม่จาก demo/rigs/kaelrin.json (ต้องรันทุกครั้งที่แก้รอยตัด/fill)
npm run fx                  # เอฟเฟกต์ + ไอคอน จาก art/raw/P08B, P09A-C -> demo/assets/fx_*.png, icon_*.png
npm run gear                # หมวก/แว่น/ผ้าปิดหน้า จาก art/raw/P04, P05 -> demo/assets/gear_*.png (+ qa-out/headgear_check.png)
npm run outfits             # ชุด P10A-C -> จัดให้ทับท่า P02A + ตัดชิ้น rig -> kaelrin_{view}_parts_{id}.png (+ qa-out/outfits_check.png)
npm run map                 # แมพ P07A + P07B ต่อกัน -> demo/assets/map_town_meadow.jpg + demo/maps/mossbridge.json
```
- **ไม่มี Playwright?** `npm run qa:serve` (เสิร์ฟ demo + `/__qa/*` + บันทึกภาพลง `qa-out/`) แล้วเปิดเกมในเบราว์เซอร์ใดก็ได้ (รวมถึงเบราว์เซอร์ในแอปแม้แผงถูกซ่อน) รัน `await import('/__qa/inpage.js')` ในหน้า → `__qa.walk('sw', 8, .07)` แล้ว `__qa.save('ชื่อ')` ได้ contact sheet ที่ `qa-out/ชื่อ.png`; `__qa.sim()` = qa:sim; `__qa.film(...)` = เฟรมวิดีโอ 30 fps แล้วต่อเป็น mp4 ด้วย ffmpeg (ดูหัวไฟล์ `tools/qa/inpage.js`)
- Rig Editor: `http://localhost:8000/rig-editor.html` (โหมด "โครง/ชิ้นส่วน" แก้ข้อต่อ+รอยตัด, โหมด "ท่าทาง" แก้คลิป) → Export JSON ไปแทน `demo/rigs/kaelrin.json` → ถ้าแก้รอยตัดให้รัน `npm run rig`
- ในเกม กด **R** สลับวิ่ง/เดิน · **H** (หรือปุ่ม 👒) ลองใส่หมวก · มุมกล้องปรับที่ `CAM_WIDE` ใน game.js (ค่าน้อย = เห็นแมพกว้างขึ้น)
- แมพ: ข้อมูลอยู่ `demo/maps/mossbridge.json` (พื้นที่เดิน, จุดเกิดฮีโร่/สไลม์/บอส, ประกายน้ำ, `scale` = ขนาดตัวละครคงที่เพราะแมพมุมตรง) แก้จุดได้ใน `tools/build_map.py` · กด **G** ดูพื้นที่เดินได้
- เครื่องที่ไม่มี GPU ให้ตั้ง `SOFTWARE_GL=1` และถ้าโหลด CDN ไม่ได้ให้ตั้ง `PIXI_LOCAL=/path/pixi.min.js`
- `window.__mossbridge.step(sec, fps)` หยุด ticker แล้วเดินเกมแบบกำหนดเวลาได้แน่นอน ใช้จับเฟรมเพื่อตรวจท่าทาง
  เพราะถ้าจับภาพตามเวลาจริงบนเครื่องช้า เฟรมจะไม่ตรงจังหวะ
- ในเกม กด **G** เพื่อดูพื้นที่เดินได้ (polygon)
- ไลบรารี: PixiJS **7.4.2** จาก cdnjs (pin version ไว้ ห้ามใช้ `latest`)

## 4. งานภาพ: สั่ง ChatGPT ผ่านเบราว์เซอร์

ทุกอย่างที่ต้องใช้อยู่ใน `chatgpt-pack/` แล้ว (`00_README_TH.md` คือวิธีใช้ฉบับคน, `01_START_HERE_for_ChatGPT.md` คือกติกาที่วางเป็นข้อความแรก, `prompts/P01…P09`, `refs/`, `manifest.json` รายชื่อไฟล์ที่ต้องได้)

ขั้นตอนเมื่อใช้ Claude in Chrome / เบราว์เซอร์ในแอป:
1. เปิดแท็บใหม่ไปที่ chatgpt.com ให้เจ้าของ login เอง (ห้ามขอรหัสผ่าน ห้ามพิมพ์รหัสแทน)
   - ใช้บัญชี **Plus** (บัญชี Free สร้างภาพได้ราว 3 ภาพ/วัน และแนบไฟล์ได้น้อย ทำ P01–P03 ไม่จบในวันเดียว)
   - เครื่องมือแนบไฟล์ของ Claude in Chrome อ่านได้เฉพาะไฟล์ในโฟลเดอร์ของ session ถ้าแนบจาก `chatgpt-pack/refs/` ไม่ได้ ให้คัดลอกไป scratchpad ก่อน
2. เริ่มแชทใหม่ แนบรูปทุกไฟล์ใน `chatgpt-pack/refs/` ถ้าเครื่องมือเบราว์เซอร์แนบไฟล์จากเครื่องไม่ได้ ให้ขอเจ้าของลากรูปใส่แชทเอง
3. วางข้อความจาก `01_START_HERE_for_ChatGPT.md` รอ ChatGPT ตอบ "Ready"
4. ส่ง prompt ทีละภาพตามลำดับ **P01 → P02 → P03 ก่อน** (สำคัญที่สุด) 1 ข้อความต่อ 1 ภาพ
5. ตรวจภาพทุกใบเทียบกับกติกา ถ้าผิด ให้ใช้ประโยคแก้ในตารางของ `00_README_TH.md §4` ต่อในแชทเดิม อย่ารับภาพที่ผิดมาแก้เอง
6. ดาวน์โหลดภาพเป็น PNG ขนาดเต็ม ตั้งชื่อตาม `SAVE AS:` แล้วเก็บใน `art/raw/` (โฟลเดอร์นี้อยู่ใน .gitignore)
   - ถ้าปุ่มดาวน์โหลดใช้ไม่ได้ ให้รัน JavaScript ในหน้า: `fetch(img.src)` → blob → สร้าง `<a download>` แล้วคลิก จากนั้นย้ายไฟล์จาก Downloads มาที่ `art/raw/`
   - ถ้ายังไม่ได้ ให้ขอเจ้าของกดดาวน์โหลดเอง
7. ล้างภาพ: `python3 tools/sprite_clean.py art/raw/<file>.png -o art/out/<name> --key "#FF00FF" --edge-despill 3 ...` (หมวกสีม่วงใช้ `--key "#00FF00"`) ดูตัวเลือกใน docstring ของไฟล์
   - `--edge-despill 3` จำเป็นกับภาพจาก ChatGPT: เส้นขอบเข้มผสมกับพื้นม่วงจนเป็นวงชมพูรอบตัว และช่องว่างแคบ ๆ (ระหว่างแขนกับลำตัว) ถูกวาดเป็นม่วงเข้ม
   - ภาพ P01–P03 ล้างด้วย `python3 tools/build_kaelrin_parts.py` (จับคู่หัว P02B กับหัวใน P01 ให้ขนาด/ตำแหน่งตรง) แล้ว `python3 tools/build_demo_assets.py`
8. commit ภาพที่ผ่านแล้ว (ไม่ใช่ภาพดิบ) ไว้ใต้ `demo/assets/` หรือ `art/samples/`

**กฎภาพ** (ละเอียดใน `docs/02-art-style-guide.md`, `docs/03-sprite-spec.md`):
- ตัวละคร 4 มุมที่วาดจริง: **SW, SE, W, NE** (เกมกลับภาพเป็น E, NW)
- แสงจากบน-หน้า (สมมาตร) เพื่อให้ภาพที่กลับด้านยังดูถูก
- พื้นหลังสีเดียวเรียบ ไม่มีเงาพื้น ไม่มีแสงฟุ้งรอบตัว (เอฟเฟกต์ทำในเกม)
- หัวแยกจากตัว (P02) จะเปิดให้ใช้ระบบหมวกได้

## 5. งานหลัก: แอนิเมชันให้เนียน (ลำดับที่แนะนำ)

### 5.0 ตอนนี้ทำงานอย่างไร (ต้องเข้าใจก่อนแก้) — ตั้งแต่ v0.3
ฮีโร่เป็น **cutout rig** (`demo/rig.js`, ข้อมูล `demo/rigs/kaelrin.json`):
- **ชิ้นภาพ:** `tools/build_kaelrin_rig.py` ตัดภาพตัวไม่มีหัวต่อมุมเป็น armL/armR/legL/legR/torso ตาม polygon ใน rig (ชิ้นหน้าสุดได้พิกเซลก่อน, torso = ที่เหลือ) แล้ว **เติมส่วนที่ถูกบัง** (ต้นขาใต้เสื้อ, ลำตัวหลังแขน) ด้วยสีจากในชิ้นเอง → atlas `kaelrin_{view}_parts.png` ประกอบกันตอนพักได้ภาพเดิมทุกพิกเซล
- **กระดูก:** hip, chest, upperArm/foreArm ×2, thigh/shin/foot ×2 จากข้อต่อต่อมุมใน `views.{v}.joints`; แต่ละชิ้นเป็น mesh ผูกน้ำหนักกับกระดูกของมัน (ข้อต่องอแบบนุ่ม); หัวเป็น mesh ปักที่คอ (ผมหน่วงด้วยสปริง); อาวุธปักที่ปลายแขน `weapon.hand` และวาด **ใต้กำปั้น** (ด้ามลอดกำปั้น)
- **ระนาบเดิน:** ขา/แขนขยับใน "ระนาบหน้า-บน" ของตัวละครที่ฉายด้วยเวกเตอร์ `fwd` ของมุมนั้น (ก้าวเข้าหากล้องจึงลงจอ) + `right` สำหรับก้าวเฉียง; ขาใช้ **2-bone IK** ไปยังข้อเท้าเป้าหมาย; ท่าพักของภาพ (ขากาง) เก็บเป็น offset คงที่ ภาพตอนพักจึงตรงต้นฉบับเป๊ะ
- **Locomotion (`MossRig.Locomotion`):** เท้าเก็บเป็นพิกัดโลก — เท้าที่แตะพื้นไม่ขยับเลย, เท้าที่ยกเหวี่ยงไปจุดลงที่ทำนายจากความเร็ว → ก้าว×จังหวะ = ความเร็วจริงเสมอ; เดิน/วิ่ง blend ตามความเร็ว (`motion.walk/run`: speed, cadence, swing, lift + แทร็กลำตัว/แขน), ยืน = `motion.idle`, ออกตัว/หยุด/เปลี่ยนทิศ = คลิปเสริมสั้น ๆ (`motion.start/stop/turn`); หยุดแล้วเท้าที่ค้างจะก้าวตามมาเอง (settle)
- **ฮีโร่ในเกม (`Hero` ใน game.js):** ความเร็วเร่ง 0.12 วิ / ชะลอก่อนถึงจุดหมาย; เปลี่ยนมุมกล้อง = cross-fade 70 ms + squash; จุดยืนของแต่ละมุม `views.{v}.root` = กึ่งกลางระหว่างเท้า (ภาพไม่กระโดดตอนหมุน); R = สลับวิ่ง/เดิน
- **ท่าโจมตี/สกิล/โดนตี (v0.4):** คลิปใน `motion.actions` (slash1–3, tidecleave, mossquake, galedash, mend, hurt) เป็นค่า channel จริงทับท่ายืน · คีย์ใส่ easing ได้ `[t, ค่า, "in"|"out"|"io"|"lin"]` (ตีเร็วใช้ "in") · `step` = ตัวพุ่งไปข้างหน้า, `footRF/footLF` วัดจากจุดเริ่มท่า (เท้าที่ค่าไม่เปลี่ยน = เหยียบอยู่กับที่ระหว่างพุ่ง) · `spin` = หมุนตัวผ่านภาพทุกมุม (Tidecleave) · `hits` = เวลาโดน, `smear` = รอยดาบ P09A, `kick` = กระตุกผม/ผ้าพันคอ · อาวุธ **อยู่ใต้กำปั้นตลอด** และยกไปหลังหัว (มุมที่แขนถืออาวุธอยู่หลังตัว) จึงไม่พาดหน้าแล้ว
- **ท่าพร้อมสู้ (v0.5):** `motion.stance` (แขนถือดาบยกนิดหน่อย มือซ้ายตั้งการ์ด) + `views.{v}.stance` (มุมข้อมือที่ทำให้ดาบชี้ขึ้นไปข้างหน้าในแต่ละมุมกล้อง) บวกทับทุกท่ายืน/เดิน/วิ่ง; ท่าโจมตีออกจาก stance ใน 0.1 วิแรกและกลับเข้าใน 0.15 วิสุดท้าย · จุดจับอาวุธ `views.{v}.weapon.grip` = กึ่งกลางกำปั้น, `weaponGrip` = กึ่งกลางด้ามที่พันหนัง (กำปั้นคลุมทั้งด้าม)
- **ชุด (v0.6):** `tools/build_outfits.py` จัดภาพชุดให้ทับตัว P02A (หา scale+เลื่อนที่รูปร่างทับกันมากสุด) แล้วตัดด้วยรอยตัด/ข้อต่อเดิม → `views.{v}.outfits.{id}` (atlas + rect ต่อชิ้น) · `Hero.setOutfit(id)` สร้าง RigView ใหม่ · **ถ้าแก้รอยตัดใน rig ต้องรัน `npm run rig` แล้ว `npm run outfits` ใหม่** · สั่งชุดใหม่: ใช้ image edit ของ ChatGPT บนภาพ P02A ('repaint only the clothing') ได้ท่าตรงกว่าวาดใหม่ แล้วตั้ง `exact` ใน OUTFITS
- **หมวก (v0.5):** `RigView.setGear(slot, texture, hair)` ช่อง top/mid/low เป็น mesh บนแคนวาสหัว ใช้จุดเดียวกับหัว (ขยับตามหัว+ผม) · หมวกที่ `hair: "capped"` สลับหัวเป็นผมยุบ (P02C) · `Hero.wear(slot, id)` + แผงเลือกใน index.html (จำไว้ใน localStorage)
- **ความหมายของ channel เหมือนกันทุกมุม:** `armXSwing` + = มือไปข้างหน้า (π/2 = ชี้ตรงไปหน้า, π = ชูเหนือหัว), `armXBend` + = งอศอก, `lean` + = เอนหน้า, `head` + = ก้มหัว, `weaponRot` + = ปลายดาบเงยไปข้างหน้า (ดูหัวไฟล์ rig.js)
มอนสเตอร์ยังเป็นแบบเดิม: `Sproutling.render` (ยุบ/ยืด/สั่น) และ `Mossback.render` (ขา 4 ข้างแบบเฉือนภาพ + หัวเอียง)

**จุดอ่อนที่เหลือ:** ส่วนที่ถูกบังเติมด้วยการไล่สี (เห็นเป็นรอยเบลอเมื่อแขนแกว่งกว้าง — แก้ได้ด้วยภาพ "ลำตัวไม่มีแขน" จาก ChatGPT), แขนเป็นภาพเดียวหมุนรอบไหล่ (ตอนชูสุดแขนดูเป็นกระดาษพับ — ถ้าต้องการให้ ChatGPT วาดแขนท่ายกเพิ่มแล้วสลับภาพ), ยังไม่มีท่าตาย/ฟื้น, หมูป่าเดินเหมือนภาพกระดิก, สไลม์กระโดดแข็ง ๆ

### 5.1 ระบบ skeletal rig แบบแยกชิ้น (แก้ปัญหาหลัก) — ทำแล้วใน v0.3 (ดู §5.0; ไฟล์จริงต่างจากร่างด้านล่างเล็กน้อย: ข้อต่อเก็บเป็นพิกัดบนภาพ `joints` + กระดูก `{from, to}`, ชิ้นภาพ `slots[].poly/fill/rect/pos`, ท่าอยู่ใน `motion`)
อัปเกรดจาก "ภาพเดียวบิด" เป็น **กระดูก (bones) + ชิ้นภาพ (slots) + mesh ต่อชิ้น** แนวทางเดียวกับ Spine แต่เขียนเอง (เบา ไม่มีค่าไลเซนส์)
- ชิ้นของฮีโร่ต่อมุม: head (จาก P02B/C), torso, upper arm + forearm/hand ×2, thigh + shin/foot ×2, scarf tail, weapon (P03)
- ได้ชิ้นจาก: ตัดภาพ P02A (ตัวไม่มีหัว) ตามแนวข้อต่อ แล้วให้ ChatGPT ช่วย "เติมส่วนที่ถูกบัง" (image edit: `fill in the hidden part of the upper arm behind the torso, same style`) หรือสั่งชีตชิ้นส่วนตาม `docs/04-chatgpt-prompts.md §6`
- รูปแบบข้อมูลที่แนะนำ (`demo/rigs/kaelrin.json`):
  ```jsonc
  { "views": { "sw": { "image": "kaelrin_sw_parts.png",
      "bones": [ { "name": "hip", "parent": "root", "x": 0, "y": -62 },
                 { "name": "torso", "parent": "hip", "x": 0, "y": -10, "len": 50 },
                 { "name": "thighL", "parent": "hip", "x": -12, "y": 4, "len": 22 }, ... ],
      "slots": [ { "name": "thighL", "bone": "thighL", "rect": [x,y,w,h], "pivot": [px,py], "z": 2 }, ... ],
      "drawOrder": ["shadow","legBack","armBack","torso","head","headgear","armFront","weapon"] } },
    "animations": { "walk": { "loop": true, "dur": 0.72, "bones": { "thighL": [[0,-25],[0.36,25],[0.72,-25]], ... } } } }
  ```
- ใช้ **2-bone IK** ที่ขา: กำหนดตำแหน่งเท้าบนพื้นแล้วคำนวณมุมต้นขา/หน้าแข้ง → **เท้าไม่ลื่น** (ล็อกเท้าตอนแตะพื้น และให้ความยาวก้าว × จังหวะ = ความเร็วเดินจริง)
- ทำเครื่องมือ **Rig Editor** หน้าเดียว (แนวเดียวกับ Headgear Lab): คลิกวาง pivot/ข้อต่อ, ลากหมุนกระดูก, scrub timeline, export JSON
- หัวต่อกับ bone `head` → หมวกจาก Headgear Lab เสียบตรงนี้ (ระบบ `fit` และ `hair: full|capped|hidden` เดิมใช้ต่อได้เลย)

### 5.2 หลักแอนิเมชันที่ต้องมี (เกณฑ์ตรวจรับ)
| ท่า | ต้องเห็น |
|---|---|
| ยืน (idle) | หายใจ 1.5–2 วินาทีต่อรอบ, ผม/ผ้าพันคอขยับตามแบบหน่วง (spring), ไม่นิ่งสนิท |
| เดิน | งอเข่า, แขนแกว่งสวนขา, ตัวยกขึ้นตอนขาผ่านกัน, เท้าไม่ลื่น, จังหวะก้าวตรงกับความเร็ว, ตัวเอนนิดหน่อยตามทิศ |
| วิ่งออกตัว/หยุด | มีท่าออกตัว (เอนหน้า) และท่าหยุด (ถ่วงตัว) 0.1–0.15 วินาที ไม่ใช่หยุดทันที |
| เปลี่ยนทิศ | ไม่สลับภาพทันที: ใช้ squash เล็ก ๆ หรือ cross-fade 60–80 ms ตอนสลับมุม |
| โจมตี | ง้าง (anticipation ≥ 80 ms) → ฟาด (เร็ว 40–80 ms + smear/รอยดาบ) → จุดกระทบ (hit-stop 50–100 ms) → ตามแรง (follow-through) → คืนท่า; ผม/ผ้าพันคอตามแรงเหวี่ยง |
| โดนตี | สะดุ้งตามทิศที่โดน, กระพริบ, ถอยเล็กน้อย |
| ตาย/ฟื้น | มีท่าล้มและท่าลุก ไม่ใช่แค่จางหาย |

### 5.3 มอนสเตอร์
- **สไลม์ (Sproutling):** เปลี่ยนเป็น soft-body: จุดบน mesh ต่อกันด้วยสปริง (verlet) ให้เด้งดึ๋งจริง; กระโดด = ยุบ→พุ่ง (ยืด)→ลอย→กระแทก (แบนแล้วสั่นคืน); ใบไม้บนหัวหน่วงตามแรงเฉื่อย
- **หมูป่ามอส (บอส):** ทำ rig แยกชิ้น ได้แก่ ลำตัว, หัว (+กราม ถ้าได้), ขา 4 ข้าง (2 ท่อน), หาง และหนามบนหลัง (หน่วงตามแรง)
  - เดิน: ขาทแยงคู่ขยับพร้อมกัน (หน้าซ้าย+หลังขวา)
  - พุ่งชน: วิ่งแบบ gallop + ฝุ่นใต้เท้าตามจังหวะ
  - กระทืบ: ยืนสองขาหลังแล้วทิ้งตัว
  - ขวิด: ก้มหัวง้างแล้วสะบัดขึ้น
  - ต้องมีภาพมุมหลัง (P06B) ด้วย เวลาเดินหนีกล้องจะไม่ดูแปลก
- มอนทุกตัวต้องมีท่า: ยืน, เดิน, ง้าง (เตือนผู้เล่น), โจมตี, โดนตี, ตาย

### 5.4 ทางเลือกเสริม (ถ้า rig ยังไม่พอ)
- ใช้ AI วิดีโอ (เช่น Sora ใน ChatGPT) สร้าง "วิดีโออ้างอิง" ท่าเดิน/ฟันของตัวละคร เพื่อศึกษาจังหวะ แล้วนำมาตั้ง keyframe ใน rig (อย่าใช้เฟรมจากวิดีโอตรง ๆ เพราะแต่ละเฟรมหน้าตาไม่ตรงกัน)
- ทางที่หนักกว่า: ทำโมเดล 3D จากภาพ → rig → เรนเดอร์เป็น sprite (ดู `docs/01-feasibility.md §3` ทางเลือก C)

### 5.5 วิธีตรวจงานแอนิเมชัน (ทำทุกครั้งก่อนบอกว่าเสร็จ)
1. `npm run qa:frames` + `qa:sheet` ดู contact sheet ทุกท่าที่แก้ ทั้ง 4 มุมที่วาดจริงและมุมที่กลับภาพ
2. `npm run qa:video` แล้วดูวิดีโอ (เท้าลื่นไหม, กระตุกตอนเปลี่ยนท่าไหม)
3. `npm run qa:sim` ต้องได้ "no errors"
4. ส่งภาพ/วิดีโอให้เจ้าของดู แล้วถามความเห็น เพราะเจ้าของเป็นคนตัดสินว่า "เนียนแล้ว"
