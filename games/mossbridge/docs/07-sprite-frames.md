# 07 — ฮีโร่แบบเฟรม (sprite sheet วาดทุกท่า) — แผนใหม่ 2026-11-06

> เจ้าของตรวจ v0.6 แล้ว: **การถือดาบและการเดินของ rig ยังไม่ผ่าน** และอยากได้ sprite แบบเกม MMORPG 2D คลาสสิก
> (โครงสร้างแบบ Ragnarok Online) แต่เป็นสไตล์ภาพของเราเอง → เปลี่ยนฮีโร่เป็นแอนิเมชันแบบเฟรมที่ ChatGPT วาดทุกท่า
> rig เดิม (`demo/rig.js`) ใช้ต่อได้ระหว่างเปลี่ยน และยังใช้กับหมวก/ชุดจนกว่าเฟรมจะครบ

## 1. ไม่ใช้ไฟล์ของเกมอื่น

- **ห้ามนำไฟล์ sprite/ภาพของ Ragnarok Online หรือเกมอื่นเข้า repo และห้ามแนบให้ ChatGPT เป็นต้นแบบ**
  ภาพเป็นลิขสิทธิ์ของเขา และถ้าใช้เป็นต้นแบบ ภาพที่ได้จะติดหน้าตาเกมนั้น ซึ่งขัดกับกฎ "ภาพ ชื่อ โลก เป็นของเราเอง"
- สิ่งที่เรายืมคือ **โครงสร้างทั่วไปของแนวเกม** เท่านั้น: วาด 5 ทิศแล้วกลับภาพเป็น 8, แยกเลเยอร์ตัว/หัว/หมวก,
  จุดยึดต่อเฟรม, รายการท่า (ยืน เดิน ตี โดนตี ตาย ร่ายเวท นั่ง) — ทั้งหมดเขียนไว้ในเอกสารนี้แล้ว ไม่ต้องใช้ไฟล์ต้นฉบับ
- ต้นแบบหน้าตาใช้ของเราเท่านั้น: `chatgpt-pack/refs/REF_03` (Kaelrin 4 มุม), `art/raw/P01` (ตัวเต็ม), `P02B` (หัว), `P03` (ดาบ)

## 2. ทิศ

| | ทิศ |
|---|---|
| วาดจริง 5 ทิศ | **S** (หันหน้าเข้ากล้อง), **SW** (หน้าเฉียงซ้ายล่าง), **W** (ข้าง หันซ้าย), **NW** (หลังเฉียงซ้ายบน), **N** (หันหลัง) |
| กลับภาพ 3 ทิศ | SE ← SW, E ← W, NE ← NW |

- เลือกทิศจากมุมการเดินที่ใกล้ที่สุดใน 8 ทิศ (ทีละ 45°)
- แสงจากบน-หน้าแบบสมมาตร (กฎเดิม) ภาพที่กลับด้านจึงยังดูถูก ดาบจะสลับไปมือซ้ายตอนกลับภาพ ซึ่งยอมรับได้ (เกมแนวนี้ทำแบบนี้ทั่วไป)
- หมายเหตุ: ภาพชุดเดิม (P01–P10) วาด SW, SE, W, NE สำหรับ rig ส่วนฮีโร่แบบเฟรมใช้ชุด 5 ทิศใหม่นี้

## 3. เลเยอร์ (ลำดับวาด ล่าง → บน)

1. **body** — ตัวไม่มีหัว ใส่ชุด และ**ถือดาบอยู่ในมือแล้ว** (วาดมาในเฟรมเดียวกัน กำปั้นจึงกำด้ามจริง ไม่ต้องหมุนภาพดาบ)
2. **head** — หัวต่อทิศ (ผมปกติ/ผมยุบ) ปักที่จุดคอของแต่ละเฟรม
3. **headgear** — ช่อง top/mid/low บนแคนวาสหัวเดิม (`docs/03` §6) ใช้ภาพ P04/P05 ที่มีอยู่ได้ (ต้องเพิ่มทิศ S/N/NW ภายหลัง)
4. เอฟเฟกต์ (รอยดาบ, แสง) — เกมวาดเอง ไม่อยู่ในภาพตัวละคร

ระยะหลัง (ถ้าต้องเปลี่ยนอาวุธได้): แยกอาวุธเป็นเลเยอร์ต่อเฟรม ตอนนี้ยังไม่ทำ

## 4. ท่าและจำนวนเฟรม (รุ่นแรก)

| ท่า | id | เฟรม | เวลา | วน | ชีต (ภาพเดียว) | หมายเหตุ |
|---|---|---|---|---|---|---|
| ยืนพร้อมสู้ | `idle` | 4 | 0.2 วิ/เฟรม | ✓ | 2×2, 1024×1024 | หายใจ ดาบอยู่ในมือ ขยับน้อยมาก |
| เดิน | `walk` | 8 | ตามระยะทาง (ก้าว 1 รอบ = 8 เฟรม) | ✓ | 4×2, 1536×1024 | contact → down → passing → up × 2 ขา |
| ฟัน | `attack` | 6 | 0.08 / 0.08 / 0.05 / **0.12 (โดน)** / 0.08 / 0.10 | ✗ | 3×2, 1536×1024 | เฟรม 4 = จังหวะโดน + hit-stop |
| โดนตี | `hurt` | 2 | 0.08 / 0.18 | ✗ | 2×1, 1536×1024 | |
| ล้ม | `die` | 4 | 0.12 / เฟรมสุดท้ายค้าง | ✗ | 2×2, 1024×1024 | |
| ร่าย/ฮีล | `cast` | 4 | 0.12 | ✗ | 2×2, 1024×1024 | |

- วิ่ง = ท่าเดินเล่นเร็วขึ้น (ทำชีตวิ่งแยกทีหลังถ้าจำเป็น)
- คอมโบ 3 จังหวะ: รุ่นแรกใช้ `attack` ชีตเดียว ภายหลังเพิ่ม `attack2` (ฟันเสย), `attack3` (กระโดดทุบ)
- ปริมาณงาน: idle + walk + attack = 18 เฟรม × 5 ทิศ = **15 ภาพ** ต่อชุด (+ หัว 5 ทิศ) → **ทำ pilot ทิศเดียวก่อน (§9)**

## 5. กติกาการสั่งชีต (ทุกภาพ)

- **1 ภาพ = 1 ท่า × 1 ทิศ** แบ่งเป็นตารางช่องเท่ากัน อ่านซ้าย→ขวา บน→ล่าง ไม่มีเส้นตาราง
- ตัวละครขนาดเท่ากันทุกช่อง สูงราว **2/3 ของความสูงช่อง** เท้าอยู่บนเส้นฐานเดียวกันทุกช่อง และอยู่กลางช่อง (เดินอยู่กับที่ ไม่ไหลออกข้าง)
- การเปลี่ยนระหว่างเฟรมของ idle ต้อง**เล็กมาก** (ไม่กี่พิกเซล) เพื่อให้วนลื่น
- ดาบ = ดาบทองเหลืองใน P03 อยู่ใน**มือขวา** กำปั้นกำรอบด้ามหนังเต็มมือ
- ห้าม: เส้นความเร็ว, รอยดาบ, แสงฟุ้ง, เงาพื้น, ตัวอักษร (เกมทำเอฟเฟกต์เอง)
- พื้นหลัง magenta #FF00FF เรียบ (กฎ global ใน `01_START_HERE_for_ChatGPT.md`)
- ต้นแบบที่ต้องบอกในทุก prompt: P01 (หน้าตา/ชุด), P03 (ดาบ) และชีต idle ของทิศเดียวกัน (ถ้ามีแล้ว) เพื่อให้หน้าตาไม่เพี้ยนข้ามชีต
- **ลำดับการได้เลเยอร์:** สั่ง "ตัวเต็มมีหัว" ก่อน (หน้าตาคงที่และให้เจ้าของดูท่าได้) → ถ้าผ่าน ใช้ **image edit** ของ ChatGPT บนชีตนั้น:
  `Remove only the head and hair, keep a short neck stump. Change nothing else.` → ได้ body layer ท่าตรงกันทุกพิกเซล
  (บทเรียนจาก P10C: แก้ภาพเดิมด้วย edit รักษาท่า/ขนาดได้ดีกว่าสั่งวาดใหม่มาก)

## 6. จุดยึดต่อเฟรม (เครื่องมือหาเอง)

| จุด | วิธีหา |
|---|---|
| `feet` | แถวล่างสุดของเท้าที่แตะพื้น (กึ่งกลางระหว่างเท้าในช่วง idle) — ใช้วางตัวละครบนพื้น |
| `neck` | ยอดกลางตอคอในเฟรมไม่มีหัว (แบบ `neck_point()` ใน `tools/build_kaelrin_parts.py`) — วางหัว |
| `headTilt` | (รุ่นสอง) เทียบหัวในเฟรมตัวเต็มกับภาพหัวต่อทิศ ด้วย template match แบบที่ใช้กับ P02B |
| `tip` | ปลายดาบ (จุดเหล็กที่ไกลจากกำปั้นที่สุด) — ใช้ลากรอยดาบ P09A |

## 7. เครื่องมือที่ต้องทำ: `tools/build_hero_frames.py`

1. อ่าน `art/raw/P11*_*.png` (ชื่อบอกทิศ/ท่า/จำนวนเฟรม) → key magenta (`sprite_clean.remove_spill`, `--edge-despill 3`)
2. ตัดตามช่องตาราง → หา bbox + `feet` + `neck` + `tip` ต่อเฟรม
3. สเกล: ต่อทิศใช้ความสูงของ idle เฟรม 1 เป็นฐาน → ตัวสูง 260 px (เท่ากับเดโมปัจจุบัน) ทุกท่าในทิศนั้นใช้สเกลเดียวกัน
4. วางเฟรมบนแคนวาส 320×320 ให้ `feet` อยู่ที่ (160, 300) → pack เป็น atlas ต่อทิศ
5. เขียน `demo/sprites/kaelrin.json` เช่น
   ```jsonc
   { "canvas": [320, 320], "feet": [160, 300],
     "dirs": { "sw": { "atlas": "kaelrin_sw_frames.png",
       "actions": { "walk": { "loop": true, "frames": [ { "rect": [x,y,w,h], "neck": [nx,ny], "tip": [tx,ty] }, ... ],
                              "stride": 92 },
                    "attack": { "loop": false, "durations": [0.08,0.08,0.05,0.12,0.08,0.10], "hit": 3, ... } } } } }
   ```
6. QA: contact sheet + GIF ต่อท่า/ทิศ ลง `qa-out/` และตรวจ "หน้าตาเพี้ยน" (สีผม/ชุดต่างจาก P01) ด้วยฮิสโทแกรมสีต่อเฟรม

## 8. ในเกม

- `SpriteHero` ใหม่ (แทน `Hero` แบบ rig เมื่อเปิด flag): เล่นเฟรมตาม action; เดินเลื่อนเฟรมตาม**ระยะทาง** (`stride` px ต่อ 8 เฟรม) เท้าจึงไม่ลื่น
- หัว + หมวกเป็น sprite ปักที่ `neck` ของเฟรมปัจจุบัน
- ฟัน: เฟรม `hit` ทำดาเมจ + hit-stop + รอยดาบจาก `tip` เฟรม 3→4
- เปลี่ยนทิศ: เปลี่ยนชีตทันทีบนเฟรมเดียวกัน (เกมแนวนี้ทำแบบนี้) + squash เล็ก ๆ 60 ms
- เก็บ rig ไว้เป็นทางเลือก (ปุ่มสลับใน debug) จนกว่าเฟรมจะครบทุกท่า/ทิศ
