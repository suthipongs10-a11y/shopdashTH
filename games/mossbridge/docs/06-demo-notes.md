## เทคนิคหลัก: mesh deformation บนภาพวาดภาพเดียว

ตัดสินใจเปลี่ยนจากแผนเดิม (cutout แยกชิ้น ใน `01-feasibility §3`) เป็นแบบนี้สำหรับเดโม เพราะ **ใช้ภาพที่มีอยู่ได้ทันทีโดยไม่ต้องสั่งภาพใหม่**:

- ภาพตัวละคร 1 ภาพต่อมุม ถูกวางบนตาข่าย 22×22 จุด (`PIXI.SimplePlane`)
- ทุกเฟรมคำนวณตำแหน่งจุดใหม่จาก "ท่า" (pose) ไม่กี่ค่า: `air` (ลอยทั้งตัว), `bob` (เด้งลำตัวแต่เท้าติดพื้น), `lean` (เอนรอบสะโพก), `head` (เอียงหัวรอบคอ), `squash` (ยุบ/ยืด), `legA/legB` + `liftA/liftB` (ก้าว/ยกขาซ้ายขวา), `reachF/reachU` (มือถืออาวุธยื่น), `raise/spin` (หมุนอาวุธรอบด้ามจับ), `step` (พุ่งไปข้างหน้า)
- ท่าโจมตีคือ keyframe ของค่าเหล่านี้ + easing (`CLIPS` ใน game.js) แล้ว blend เข้า/ออกจากท่าเดินแบบนุ่ม ๆ
- จุดสำคัญต่อมุม (สะโพก, รอยแยกขา, คอ, ปลายดาบ) อยู่ในตาราง `RIG`

ข้อดี: ภาพสม่ำเสมอ 100% (ไม่มีเฟรมเพี้ยน), เพิ่มท่าใหม่ไม่ต้องสั่งภาพ, ระบบหมวกยังใช้ได้ (หมวกยึดกับจุดหัวที่ deform แล้ว)
ข้อจำกัด: แขนข้างที่ไม่ถืออาวุธยังขยับน้อย, ขาก้าวได้ไม่กว้างเท่าวาดมือ, หมุนตัวไปด้านหลังกลางท่าไม่ได้

## ปัญหาที่รู้แล้ว (Known issues)

- ภาพ SE กับ NE มีเศษด้ามอาวุธ/ถุงมือติดอยู่เล็กน้อย (มองเห็นเฉพาะตอนซูมมาก)
- ยังไม่มีการบังตัวละครโดยฉากหน้า (ราวรั้ว, แผงร้านค้า) จึงกำหนดพื้นที่เดินให้ห่างของพวกนี้ไว้ก่อน
- ภาพแมพความละเอียด 1672 px จะเริ่มนุ่มเมื่อซูมเกิน ~1.4 เท่าบนจอใหญ่
- ทดสอบอัตโนมัติด้วย Chromium แบบไม่มีจอ + software rendering เท่านั้น ยังไม่ได้วัด FPS บนมือถือจริง
