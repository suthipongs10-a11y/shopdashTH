# ClipFactory — หาเทรนด์ แล้วทำคลิปตามกระแส

เครื่องมือสำหรับ **affiliate รายเดี่ยว** ที่ต้องผลิตคลิปปักตะกร้าจำนวนมากคนเดียว
ทำสองอย่าง: **Research** หาว่าตอนนี้อะไรกำลังมาแรง และ **Video Maker** ทำคลิปตามกระแสนั้น

หาเทรนด์ → เลือกสินค้าให้ตรงกระแส → เลือกสูตรที่พิสูจน์แล้วว่าขายได้ → เขียนสคริปต์ พากย์เสียงไทย → เรนเดอร์ mp4 แนวตั้ง

> **ไม่โพสต์ให้อัตโนมัติ** — TikTok Content Posting API ไม่มีช่องให้ปักตะกร้า
> โพสต์อัตโนมัติจึงได้คลิปที่ไม่มีตะกร้า ซึ่งไม่มีประโยชน์ เครื่องมือนี้จบที่ไฟล์พร้อมอัปโหลด
> แล้วคุณเข้าแอปไปปักตะกร้าเอง (ดู [ข้อจำกัด](#ข้อจำกัดที่รู้อยู่แล้ว))

> สูตรคลิปทั้ง 9 แบบถอดมาจากคลิป outlier จริงในไทย ก.ค.–ส.ค. 2026
> ดูที่มาได้ที่ [`../research/tiktok-shopee-video/README.md`](../research/tiktok-shopee-video/README.md)

## ทำอะไรได้บ้าง

| ขั้น | สิ่งที่ระบบทำให้ |
|---|---|
| 1. หาเทรนด์ | **ปฏิทินแคมเปญ** บอกว่า 9.9 / เงินออก / วันแม่ เหลืออีกกี่วันและถึงเวลาลงมือหรือยัง · **ค้นเทรนด์สด** ให้ Gemini ค้น Google ว่าตอนนี้อะไรมาแรงในไทย แล้วสรุปเป็นการ์ด: มุมเล่า สินค้าที่เกาะกระแสได้ ตัวอย่าง hook แฮชแท็ก และสูตรคลิปที่แนะนำ · กด **"ทำคลิปจากเทรนด์นี้"** เพื่อตั้งต้นงานต่อได้เลย |
| 2. ข้อมูลสินค้า | ชื่อ ราคา หมวด จุดขาย กลุ่มลูกค้า · **วางข้อความที่ copy จากแอปแล้วให้ AI แยกฟิลด์ให้** |
| 3. เลือกสูตร | 9 สูตรพร้อมหลักฐานคลิปจริง (ยอดวิว + outlier score) · แนะนำสูตรอัตโนมัติตามหมวดสินค้า · กรองตามแพลตฟอร์ม |
| 4. สคริปต์ | Gemini เขียนสคริปต์ไทยตามกฎของสูตรนั้น พร้อม **hook 5 เวอร์ชัน** ให้เลือก แก้ไขได้ทุกบรรทัด · ได้แคปชั่นตอนโพสต์ + แฮชแท็ก · โหลดสคริปต์ถ่ายทำเป็น .txt ไว้ถ่ายเองได้ |
| 5. เสียงพากย์ | Gemini TTS อ่านให้ทีละบรรทัด เลือกเสียงได้ 8 แบบ และโทนการพูด 4 แบบ — **ไม่ต้องพูดเอง** |
| 6. รูปภาพ | อัปโหลดรูปสินค้าจริง เรียงลำดับได้ ระบบสลับรูปตามจังหวะตัดของสูตร |
| งานของฉัน | บันทึกงานหลายสินค้าไว้ในเครื่อง · งานที่ค้างถูกเก็บอัตโนมัติ ปิดแท็บแล้วเปิดใหม่ก็ยังอยู่ |
| 7. เรนเดอร์ | mp4 9:16 1080×1920 พร้อมซับไทย เขตปลอดภัย และ **เรนเดอร์ทุก hook พร้อมกันเป็นหลายคลิป** |

**สิ่งที่ระบบบังคับให้ถูกต้องตามงานวิจัยโดยอัตโนมัติ**

- Hook อยู่ใน 3 วินาทีแรกเสมอ และห้ามมีคำทักทาย (บังคับผ่าน prompt)
- เปลี่ยนภาพทุก 3–4 วินาทีตามที่สูตรกำหนด (ซอยช็อตอัตโนมัติ)
- ข้อความไม่ตกลงไปในเขตที่ UI ของแพลตฟอร์มบัง — ล่าง 25% และขวา 15%
- ความยาวคลิปคุมอยู่ในช่วงที่สูตรนั้นชนะจริง
- ซับตรงกับเสียงเป๊ะ เพราะไทม์ไลน์สร้างจากความยาวไฟล์เสียงจริง ไม่ใช่การเดา
- สูตรที่งานวิจัยระบุว่าชนะด้วย "เสียงพูดล้วน" จะไม่ยอมให้ใส่เพลงประกอบ
- คลิปสำหรับ Shopee ถูกคุมความยาวไว้ที่ 10–30 วินาทีตามที่แพลตฟอร์มแนะนำ

**เทรนด์เชื่อได้แค่ไหน**

ส่วนค้นเทรนด์ใช้ Gemini ค้น Google สด **ไม่ใช่ข้อมูลยอดวิวจริงจากแพลตฟอร์ม**
แต่ละการ์ดจึงติดป้ายความมั่นใจ (มีหลักฐานชัด / พอมีหลักฐาน / เป็นการคาดเดา)
และแสดงลิงก์ที่ใช้อ้างอิงให้กดตรวจเองได้ — ใช้เป็นทิศทาง แล้วเทียบกับสิ่งที่เห็นในฟีดจริงอีกที

ส่วน**ปฏิทินแคมเปญ**คำนวณจากวันที่ล้วน ไม่เรียก API ไม่มีวันผิดและไม่มีวันหมดอายุ

**ค่าไหนมีหลักฐาน ค่าไหนเราอนุมาน**

หน้าจอเลือกสูตรจะขึ้น `~` นำหน้าค่าที่งานวิจัยไม่ได้ระบุไว้ (เราอนุมานเองเพื่อให้ระบบทำงานได้)
ค่าที่ไม่มีเครื่องหมายวัดจากคลิปจริงที่แสดงเป็นหลักฐานใต้สูตรนั้น — ดูฟิลด์ `derived` ใน `lib/templates.ts`
โดยสรุป: ความยาวของ 4 สูตร (haul, proof-test, beat-sync, seller-pov), การจัดเสียงของ 6 สูตร,
จำนวนซีนทุกสูตร และการจับคู่แพลตฟอร์มทุกสูตร เป็นการอนุมาน ไม่ใช่ค่าที่วัดมา

## เริ่มใช้งาน

**ต้องมีก่อน:** Node.js 20 ขึ้นไป ([nodejs.org](https://nodejs.org)) · เบราว์เซอร์ Google Chrome หรือ Microsoft Edge

```bash
# 1. ดึงโค้ดสาขานี้
git clone https://github.com/suthipongs10-a11y/shopdashTH.git
cd shopdashTH
git checkout claude/tiktok-shopee-video-research-kysf4d

# 2. ติดตั้ง (ต้องมี --ignore-workspace เพราะโปรเจ็คแม่มี lockfile ของตัวเอง)
cd clipfactory
npm install -g pnpm          # ข้ามได้ถ้ามี pnpm แล้ว
pnpm install --ignore-workspace

# 3. ตรวจความพร้อม — จะสร้าง .env.local ให้ และบอกว่าต้องทำอะไรต่อ
pnpm setup

# 4. ใส่คีย์ Gemini ลงใน .env.local (ขอฟรีที่ https://aistudio.google.com/apikey)
#    แล้วรัน pnpm setup อีกครั้งเพื่อยืนยันว่าใส่ถูก

# 5. เปิดใช้งาน
pnpm dev
```

`pnpm setup` จะบอกเป็นภาษาไทยว่าติดตรงไหน — Node เก่าไป ยังไม่ใส่คีย์ ยังไม่ได้ติดตั้ง หรือพอร์ตชนกัน

### ตรวจเครื่องก่อนลงมือ

เปิด **http://localhost:3000/selftest** ด้วย Chrome หรือ Edge แล้วกด "เริ่มทดสอบ"
หน้านี้สร้างคลิปทดสอบในเครื่องโดยไม่เรียก Gemini และไม่ใช้อินเทอร์เน็ต

- ต้องผ่านครบ 5 ข้อ
- บรรทัด "เรนเดอร์ไฟล์ mp4" ต้องขึ้น **H.264 + AAC** → อัปโหลดขึ้น TikTok ได้ทันที
- ถ้าขึ้น **VP9** แปลว่าเบราว์เซอร์ไม่มีตัวเข้ารหัสลิขสิทธิ์ ให้เปลี่ยนไปใช้ Chrome หรือ Edge

### ลองใช้จริงครั้งแรก

1. **ขั้น 1** ดูปฏิทินแคมเปญ แล้วพิมพ์หมวดสินค้าที่ขายอยู่ กด "ค้นเทรนด์ตอนนี้" (ราวครึ่งนาที)
2. กด **"ทำคลิปจากเทรนด์นี้"** ในการ์ดที่ถูกใจ
3. **ขั้น 2** กรอกชื่อสินค้าจริง หรือกดปุ่มวางข้อมูลแล้ววางข้อความที่ copy จากแอป
4. **ขั้น 4** กด "เขียนสคริปต์ด้วย Gemini" แล้วเลือก hook ที่ชอบจาก 5 แบบ
5. **ขั้น 5** เลือกเสียงกับโทน กด "สร้างเสียงพากย์" (ใช้เวลาตามจำนวนบรรทัด)
6. **ขั้น 6** อัปโหลดรูปสินค้าจริง 4–6 รูป
7. **ขั้น 7** กด "เรนเดอร์คลิปนี้" ดูผล แล้วค่อยกด "เรนเดอร์ทุก hook" เพื่อได้หลายเวอร์ชัน

## ข้อกำหนดเบราว์เซอร์ (สำคัญ)

การเรนเดอร์ทำในเบราว์เซอร์ด้วย **WebCodecs** — ไม่ต้องติดตั้ง ffmpeg และวิดีโอไม่เคยถูกอัปโหลดขึ้นเซิร์ฟเวอร์

| เบราว์เซอร์ | ผล |
|---|---|
| **Google Chrome / Microsoft Edge** | ✅ ได้ H.264 + AAC — อัปโหลดขึ้น TikTok และ Shopee ได้ทันที |
| Chromium ที่ไม่มี codec ลิขสิทธิ์ (เช่นบางดิสโทรของ Linux) | ⚠️ ถอยไปใช้ VP9 + Opus ระบบจะเตือน — ไฟล์เล่นได้แต่แพลตฟอร์มอาจไม่รับ |
| Safari / Firefox | ❌ ยังไม่รองรับ WebCodecs ครบ |

**แนะนำให้ใช้ Chrome หรือ Edge**

## โครงสร้างโค้ด

```
app/
  page.tsx              หน้าทำงานหลัก (client) — ประสานทุกขั้นตอน
  selftest/page.tsx     ทดสอบว่าเครื่องเรนเดอร์ได้ ไม่เรียก Gemini
  api/script/route.ts   เขียนสคริปต์ด้วย Gemini (structured output)
  api/tts/route.ts      พากย์เสียงด้วย Gemini TTS → คืนไฟล์ wav
  api/trends/route.ts   ค้นเทรนด์ด้วย Gemini + Google Search grounding
  api/parse/route.ts    แยกข้อมูลสินค้าจากข้อความที่ผู้ใช้วาง
  api/health/route.ts   บอก UI ว่าตั้งคีย์แล้วหรือยัง
lib/
  templates.ts          ★ 9 สูตรคลิปในรูปแบบ "ข้อมูล" — เพิ่มสูตรใหม่ได้โดยไม่แตะ engine
  campaigns.ts          ปฏิทินแคมเปญอีคอมเมิร์ซไทย — คำนวณล้วน ไม่เรียก API
  storage.ts            บันทึกงานลง localStorage (เฉพาะข้อความ ไม่เก็บไฟล์)
  types.ts              โครงสร้างข้อมูลกลาง + ค่ามาตรฐาน 9:16 และเขตปลอดภัย
  gemini/               client, script, tts (PCM → WAV), parse, trends (grounded search)
  render/
    timeline.ts         สคริปต์ + ความยาวเสียงจริง → ไทม์ไลน์ช็อต
    draw.ts             วาดเฟรม: Ken Burns, headline, ซับ, เขตปลอดภัย
    text.ts             ตัดบรรทัดภาษาไทยด้วย Intl.Segmenter
    audio.ts            ผสมเสียงพากย์ + เพลง ด้วย OfflineAudioContext
    encode.ts           WebCodecs + mp4-muxer → ไฟล์ mp4
components/             ส่วนติดต่อผู้ใช้ทีละขั้น
scripts/verify-render.mjs   ทดสอบไปป์ไลน์เรนเดอร์ด้วย Chromium จริง
scripts/test-timeline.ts    ทดสอบตรรกะไทม์ไลน์และการจับคู่เสียง
scripts/test-ui.mjs         ทดสอบ UI ในเบราว์เซอร์จริง
scripts/preflight.mjs       ตรวจความพร้อมของเครื่องก่อนใช้งาน
```

> สคริปต์ใน `scripts/` ใช้ `tsconfig.scripts.json` แยกต่างหาก เพราะ import แบบมีนามสกุล `.ts`
> ซึ่ง bundler ของ Next ไม่รองรับ

### กติกาของโค้ดฐานนี้

1. **สูตรคลิปคือข้อมูล ไม่ใช่โค้ด** — ห้ามเขียน `if (templateId === 'listicle')` ที่ไหนก็ตาม ความต่างทุกอย่างต้องมาจากค่าใน `lib/templates.ts`
2. **คีย์ Gemini อยู่ฝั่งเซิร์ฟเวอร์เท่านั้น** — ไฟล์ใน `lib/gemini/` ต้อง `import 'server-only'`
3. **ข้อความที่ผู้ใช้เห็นเป็นภาษาไทยทั้งหมด** รวมถึงข้อความ error — โค้ดและชื่อตัวแปรเป็นอังกฤษ
4. **ไทม์ไลน์ต้องสร้างจากความยาวเสียงจริง** เมื่อมีเสียงพากย์แล้ว ห้ามใช้ค่าประมาณ ไม่อย่างนั้นซับกับเสียงจะเหลื่อม
5. แก้สคริปต์แล้ว **ต้องล้างเสียงที่เกี่ยวข้องทิ้ง** เพื่อกันคลิปที่เสียงกับข้อความไม่ตรงกัน
6. **การวางเสียงต้องอ้างอิงจาก `timeline.lines` (จับคู่ด้วย key) เท่านั้น** ห้ามเดาตำแหน่งจากลำดับหรือจากข้อความบนจอ — เคยเป็นบั๊กที่ทำให้เสียงเลื่อนทั้งคลิปเมื่อมีข้อความซ้ำกัน
7. **การค้นเทรนด์ต้องทำสองขั้นเสมอ** — Gemini ใช้ `googleSearch` พร้อม `responseSchema` ในคำขอเดียวไม่ได้ จึงค้นก่อน (ได้ข้อความ + แหล่งอ้างอิง) แล้วค่อยเรียกครั้งที่สองเพื่อจัดรูป
8. **ต้องโชว์แหล่งอ้างอิงและระดับความมั่นใจของเทรนด์เสมอ** — ห้ามให้ผู้ใช้เข้าใจผิดว่าเป็นข้อมูลยอดวิวจริง
9. **ข้อความ error จาก Google ห้ามส่งต่อให้ผู้ใช้ดิบๆ** — `toThaiError()` แปลงเป็นไทยเสมอ ส่วนข้อความจริง log ไว้ฝั่งเซิร์ฟเวอร์

## ทดสอบ

```bash
pnpm setup            # ตรวจความพร้อมของเครื่อง (Node, คีย์, dependencies, พอร์ต)
pnpm typecheck        # ตรวจชนิดข้อมูลทั้งแอปและสคริปต์ทดสอบ
pnpm test             # ทดสอบตรรกะไทม์ไลน์ (ไม่ต้องใช้เบราว์เซอร์)
pnpm test:ui          # ทดสอบ UI ในเบราว์เซอร์จริง (บันทึกงาน กู้คืน กรองสูตร)
pnpm build            # build production
pnpm verify:render    # เรนเดอร์คลิปจริงด้วย Chromium แล้วตรวจโครงสร้างไฟล์ mp4
SILENT=1 pnpm verify:render   # ทดสอบสูตรที่ไม่มีเสียงพูด (ต้องได้ 1 track)
```

`pnpm test` ครอบคลุมตรรกะไทม์ไลน์ (เน้นเคสที่เคยพัง: บรรทัดที่ข้อความบนจอซ้ำกันต้องยังจับคู่เสียงถูก)
และปฏิทินแคมเปญ (นับวันถูก ข้ามปีได้ เตือนตรงเวลา)

`pnpm verify:render` จะตรวจครบตั้งแต่วาด canvas ภาษาไทย ผสมเสียง เข้ารหัสวิดีโอและเสียง
ไปจนถึงแกะกล่อง (box) ของไฟล์ mp4 ว่ามี `ftyp` `moov` `mdat` ครบ มี 2 track และ `moov` มาก่อน `mdat` (fast start)

ถ้าเครื่องมี Chromium อยู่แล้ว ให้ชี้ path ตรงๆ เพื่อไม่ต้องดาวน์โหลดใหม่:

```bash
CHROMIUM_PATH=/path/to/chrome pnpm verify:render
```

## ข้อจำกัดที่รู้อยู่แล้ว

- **ไม่โพสต์อัตโนมัติ และตั้งใจไม่ทำ** — TikTok Content Posting API อัปโหลดวิดีโอได้ แต่ไม่มีฟิลด์สำหรับติดสินค้า (ปักตะกร้า) ซึ่งอยู่คนละ API กัน โพสต์อัตโนมัติจึงได้คลิปที่ไม่มีตะกร้า ต้องเข้าแอปไปปักเองอยู่ดี · เครื่องมือจึงจบที่ไฟล์ + แคปชั่นที่ก๊อปได้ทันที เพื่อให้ขั้นตอนอัปโหลดด้วยมือเร็วที่สุด
- **ยังไม่มี feedback loop** — ยังไม่ดึงยอดวิว/ยอดขายกลับมาจัดอันดับสูตรและเทรนด์
- **เทรนด์มาจากการค้นเว็บ ไม่ใช่ API ของแพลตฟอร์ม** — แม่นน้อยกว่าข้อมูล outlier จริง แต่ใช้คีย์เดิมและไม่ต้องสมัครบริการเพิ่ม
- **ยังไม่ดึงข้อมูลจากลิงก์โดยตรง** — ต้อง copy ข้อความจากแอปมาวาง (ตั้งใจไม่ scrape เพราะทั้งสองแพลตฟอร์มกันบอท)
- **เพลงประกอบต้องอัปโหลดเอง** และควรใช้จากคลังเพลงเชิงพาณิชย์ของแพลตฟอร์มเท่านั้น
- คลิปยาวเกิน ~60 วินาทีจะใช้แรมมาก เพราะเก็บไฟล์ไว้ในหน่วยความจำทั้งก้อนก่อนดาวน์โหลด

## หลักการที่ยึดไว้

งานวิจัยชี้ชัดว่าตลาดนี้ชนะด้วย **ความจริง** ไม่ใช่ความสวย
เครื่องมือนี้จึงออกแบบให้ **ประกอบคลิปจากรูปสินค้าจริงที่ผู้ใช้ถ่ายเอง** แล้วช่วยเรื่องสคริปต์ เสียง จังหวะตัด และเขตปลอดภัย
ไม่ใช่การ generate ฉากปลอมทั้งคลิป ซึ่งเป็นสิ่งที่ทำให้คลิปทำยอดได้แย่ลง
